# dsh 故障处理经验库（通用脱敏版）

> 本文件是 dsh 故障经验的**公开脱敏版**，不含任何本机路径/用户名/token。
> 供 dsh-troubleshoot 技能引用。含个人细节的完整版仅保存在使用者本地。
> **每次处理完重大错误后，应同步更新本档案与本地完整版。**

---

## 事故 1：插件包名从裸名改为作用域包后漏改 3 处引用

**根因类型**：⚠️ **改名/改结构时旧名残留**（最高频事故类型）

### 症状

- 启动报 `Cannot find package '<旧包名>'`（服务端）
- 浏览器报 `loaded without registering "@<新包名>"`（客户端）

### 根因（关键知识点）

包名是**三层系统**，改名时三层都要同步：

| 层 | 文件 | 字段 | 作用 |
|---|---|---|---|
| ① 依赖声明 | `package.json` | `name` | npm 包身份 |
| ② 服务端挂载 | `cordis.patch.yml` | `name` | loader 按**包名** import |
| ③ 客户端模块 | `lib/client.js` | `__ModuleLoader__.load({ id })` | 浏览器端注册名 |

**可保留短名的地方**（对照 modlens 官方模式）：
- `lib/index.js` 的 `export const name`（cordis 注册 id）
- slots 注册的 `id`（界面条目 id）
- HTTP 路由前缀

### 预防

- [ ] 改名后全局搜索旧包名（含 `.yml` 和 `.js`）
- [ ] 对照 modlens：**patch name / client id = 完整包名，代码内注册名 = 短名**

## 事故 2：npm 发布后 registry 查询 404（CDN 传播延迟）

**症状**：发布命令成功但 `npm view` / registry API 404
**根因**：npm registry 的**写入节点与读取节点（CDN 边缘）传播有延迟**

### 判断发布是否成功（三连验证）

1. **重复发布**：再跑 `npm publish --access public` → 报 `You cannot publish over the previously published versions: X.Y.Z` = **包确实已发布**
2. **jsDelivr 交叉验证**：`https://cdn.jsdelivr.net/npm/<包>@<版本>/package.json` → HTTP 200
3. **等待后重查**：`npm view` 通常几分钟内恢复

### 预防

- [ ] 发布后不要立刻用 `npm view` 判断成败
- [ ] 发布命令 exit=0 + 无报错 = 已成功

## 事故 3：npm 发布 E402 / E403（作用域包访问权限）

| 报错 | 原因 | 修复 |
|---|---|---|
| `402 ... private packages` | 作用域包默认按**私有包**处理 | `npm publish --access public` |
| `403 ... bypass 2fa enabled` | npm 新政策：发布必须 2FA 或 bypass-2FA token | 生成 Granular Access Token 并勾选 **Bypass 2FA** |

## 事故 4：npm EOTP（一次性验证码）

**症状**：`npm publish` 报 `EOTP: This operation requires a one-time password`
**修复**：`npm publish --otp=<手机 Authenticator 的 6 位动态码>`（30 秒内有效）
**注意**：动态码是 Authenticator 生成的 TOTP，**不是**解锁系统的 PIN。

## 事故 5：dsh 主进程管理 —— 严禁自行杀/启进程

### 铁律

> **dsh 主进程由用户手动管理。绝不自行 Stop-Process 或 Start-Job 启动 dsh。**

### 正确流程

1. 改完代码 → 同步文件 → **告诉用户"需要重启生效"**
2. 用户手动重启
3. 用户确认后我再用 API 验证

## 事故 6：隐私保护 —— 含本机信息的文件绝不发布到公开仓库

**根因**：开发期文档天然包含本机细节（绝对路径、用户目录、token、数据目录），直接复制进公开仓库即泄露

### 铁律

> **发布到公开仓库（GitHub/npm）的任何文件，绝不包含：本机路径、用户名、token、API key、数据目录结构。**

### 判断标准（发布前扫描）

| 模式 | 示例 | 处理 |
|---|---|---|
| 盘符绝对路径 | `D:\Program Files\...` | 占位符 `<安装目录>` 或删掉 |
| 用户目录 | `C:\Users\<用户名>\...` | 改为 `~` 或删除 |
| token | `ghp_xxx` / `npm_xxx` | 绝不出现（用 `<token>` 代替） |
| 数据目录 | `...\dsh-data\profiles\...` | 用 `$DSH_HOME/...` 表示 |

### 正确做法（双文件模式）

| 文件 | 用途 | 内容 |
|---|---|---|
| **本地完整版** | 自己看，含全部路径细节 | 完整保留 |
| **发布公开版** | 给别人看，零隐私 | 路径用占位符，规则通用化 |

### 编码陷阱

用 PowerShell `Set-Content -Encoding UTF8` 写中文文件会得到 **UTF-8 with BOM 且内容被 GBK 误解**，导致技能解析失败（乱码）。写中文文件必须用 write 工具（正确 UTF-8 无 BOM）。

## 通用检查清单（改动 dsh 相关代码后必做）

- [ ] **三处一致性**：git 仓库 / npm 包 / 本地安装目录，代码哈希一致
- [ ] **语法检查**：`node --check lib/index.js` 和 `node --check lib/client.js`
- [ ] **配置解析**：`dsh --profile web --dump-config`（不启动服务器，安全验证配置树）
- [ ] **API 实测**：`/dsh-backup/status`、`/dsh-backup/config` 返回 200
- [ ] **备份实测**：触发一次增量备份，检查 manifest 的 `plugins`/`skills` 字段
- [ ] **版本同步**：改代码 → git 提交推送 → npm 升版发布（`npm version patch/minor`）
